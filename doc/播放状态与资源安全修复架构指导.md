# 播放状态与资源安全修复架构指导

## 项目愿景

让本地文件、摄像头和网络流在自然结束、暂停、Seek、停止和关闭时具有可区分、可验证的生命周期语义，避免尾帧截断、工作循环误退出、重复调度和阻塞关闭。

## 设计原则

- 自然结束、可恢复中断和不可恢复停止必须使用不同状态表达。
- EOS 按生产者到消费者逐级传播，只有最终消费者排空后才能广播播放完成。
- Stop/Shutdown 保持立即取消语义，不等待自然 drain。
- Seek 使用可恢复中断进入安全点，清理旧数据后恢复原播放状态。
- 阻塞 I/O 必须存在无锁可触发的中断通道。
- 资源使用 RAII，初始化失败必须沿管线返回，不能启动半初始化线程。

## 整体架构

```text
Demuxer EOF
  -> packet queue EndOfStream
  -> Decoder 消费剩余 packet
  -> avcodec_send_packet(nullptr) drain
  -> frame queue EndOfStream
  -> AudioPlayer / VideoFrameScheduler 消费剩余 frame
  -> AudioPlaybackDrained / VideoPlaybackDrained
  -> MediaPipeline 汇合所需消费者
  -> PlaybackFinished
```

`SyncQueue` 对消费者公开 `Item / Interrupted / Stopped / EndOfStream`。其中：

- `Interrupted`：Seek/挂起唤醒，工作循环不得退出。
- `Stopped`：Stop/Shutdown 取消，工作循环立即退出。
- `EndOfStream`：先消费队列中已有数据，队列清空后再返回。

视频调度器使用单一成员定时器，确保同一时刻最多存在一条 Tick 链。摄像头媒体源复用网络媒体源的原子中断回调模式，但不改变 UI 和多路管理边界。

## 功能 Phase

### Phase 1：队列与音频状态语义

- 为 `SyncQueue` 增加有原因的阻塞出队结果和 EOS 状态。
- AudioPlayer 区分中断、停止和自然结束，完成重采样及设备缓冲收尾。

验收：Seek 中断不结束音频工作循环；自然 EOS 只在音频排空后发出完成信号。

### Phase 2：Decoder 与 Pipeline 完成协议

- Decoder 检查全部初始化错误并使用 RAII scratch frame。
- Decoder 收到 packet EOS 后执行 codec drain，再结束 frame queue。
- MediaPipeline 汇合音频和视频消费者完成信号后广播 `PlaybackFinished`。

验收：含 B 帧/AAC 的文件不因 demux EOF 立即截断；初始化失败使 Pipeline 初始化失败。

### Phase 3：调度与摄像头生命周期

- 消除 `Stop -> Start` 后遗留 Tick 链。
- CameraMediaSource 提供 FFmpeg interrupt callback 和原子中断状态。

验收：连续 Seek 不增加 Tick 链；摄像头阻塞读可由关闭请求打断。

### Phase 4：回归检查

- 覆盖队列状态优先级、EOS 排空和调度器重启。
- 执行差异、空白符和关键调用链静态检查。

## 最终呈现效果

- 文件播放完成信号发生在音视频尾部真正消费完成之后。
- Seek、Pause 和 Stop 不再因共享布尔返回值误杀工作循环。
- 多次 Seek 不累积调度器回调。
- Decoder 初始化失败可观察，Decoder scratch frame 不泄漏。
- 摄像头关闭具备明确的中断路径。

## 风险与依赖

- Qt 音频设备没有跨平台统一的显式 drain API，只能等待设备进入空闲状态并设置有界等待；真实声卡仍需人工验收。
- DirectShow 是否及时响应 FFmpeg interrupt callback 取决于设备和驱动，仍需拔插实机测试。
- 本轮不修改 UI 状态枚举，不引入 `Seeking` 状态；通过 Pipeline 内部完成汇合控制范围。
- 本轮不修改渲染 sink、播放列表和多路管理器。
