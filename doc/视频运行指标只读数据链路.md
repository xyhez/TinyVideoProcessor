# TinyVideoProcessor 视频运行指标只读数据链路

## 1. 文档信息

- 对应阶段：Fincept 风格 UI 重构 Phase 5
- 开发分支：`dev_ui_refactor`
- 状态：设计与实现已完成静态验收，待多路运行验证
- 目标：为 UI 提供真实、低频、只读且不阻塞播放链路的运行指标

## 2. 目标与非目标

本阶段只建立运行状态的读取和展示链路，不改变播放、同步、渲染、图像处理或视觉分析行为。

目标：

- 每个展示字段都有唯一所有者、明确语义、采样频率和生命周期。
- UI 只通过 `MediaPlayController` 获得按值返回的整表快照。
- 不发逐帧信号，不在解码、调度或 OpenGL 绘制路径中格式化 UI 文本。
- 流移除、暂停恢复和窗口关闭后不保留悬空更新。

非目标：

- 不新增网络协议统计、RTP/RTCP 解析或推理性能聚合。
- 不改造逐流播放状态机。
- 不用同步 GPU 查询证明帧已经完成交换或显示。
- 不修改 `MultiViewRenderer`、解码器、解复用器、队列或视觉算法。

## 3. 字段所有权与真实语义

| 字段 | 唯一所有者 | 数据来源 | 采样/刷新 | 生命周期与未知值 |
| --- | --- | --- | --- | --- |
| 预览提交累计帧数 | `VideoFrameScheduler` | 成功调用当前 `IVideoFrameSink::PresentFrame()` 后的单调原子计数 | UI 每 1 秒读取一次累计值 | 随单路 `MediaPipeline` 创建和销毁；首个样本无速率 |
| 调度丢帧累计数 | `VideoFrameScheduler` | 同步追帧和预览限帧实际丢弃的帧 | UI 每 1 秒读取一次累计值 | 随单路管线生命周期；不是网络丢包 |
| 最近提交帧尺寸 | `VideoFrameScheduler` | 提交前 `AVFrame::width/height` | 每次成功提交帧时更新原子值 | 首帧前回退到初始化源尺寸；两者均未知时不展示 |
| 源分辨率 | `MediaPipeline` | 初始化时复制 `Fileinfo::width_/height_` | 每路初始化一次 | 只表示打开时源信息，不宣称支持动态分辨率跟踪 |
| 视频编码 | `MediaPipeline` | 初始化时复制 `videoCodecId_`，无值时回退 `CodecId_` | 每路初始化一次 | Controller 用 FFmpeg 官方名称转换；未知显示 `--` |
| 预览提交 FPS | `MainWindow` 展示采样器 | 两次预览提交累计帧数之差 / 实际采样时长 | 唯一 `Qt::CoarseTimer`，1000 ms；状态切换时可额外拉取 | 首样本、计数回退或生命周期重建显示 `--`；短于 500 ms 的窗口保留上一基线；有效零增量显示 `0.0` |
| 调度丢帧率 | `MainWindow` 展示采样器 | 窗口丢帧增量 /（提交增量 + 丢帧增量） | 与 FPS 同一采样窗口 | 分母为零时显示 `--`；文案必须包含“调度” |
| 图像处理状态 | `ImageProcessingFrameSink`；Controller 为 UI 读取边界 | sink 当前实际启用状态，经管线快照上送 | 每次整表快照 | 非活动流为关闭；不读取或推断处理吞吐 |
| 视觉分析状态 | `VisionProcessingFrameSink` + `VisionPipelineManager`；Controller 为 UI 读取边界 | sink 激活状态与非空活动视觉管线的组合 | 每次整表快照 | 只表达是否启用，不表达推理健康、耗时或 FPS |
| 网络丢包率 | 暂无所有者 | 当前项目没有协议层可靠统计 | 不采样 | 显示“不可用”，禁止使用调度丢帧替代 |
| 推理吞吐/耗时 | 暂无稳定聚合所有者 | 当前结果对象没有生命周期稳定的累计统计 | 不采样 | 显示“不可用”，仅展示视觉分析启用状态 |

`Fileinfo::FrameRate` 的默认值是 `30.0`，部分媒体源在 FFmpeg 未提供有效平均帧率时会保留默认值或用户请求值，因此本阶段不把它作为实际 FPS 或源标称 FPS 展示。

## 4. 选择的数据流

```text
VideoFrameScheduler
  累计：submittedFrames / schedulerDroppedFrames
  最近：frameWidth / frameHeight
        |
        v
MediaPipeline::RuntimeMetricsSnapshot()
  合并初始化源信息与处理链状态
        |
        v
MultiStreamManager::StreamRuntimeMetricsSnapshots()
  按当前 streams_ 附加 StreamId，整表返回
        |
        v
MediaPlayController::StreamRuntimeMetricsSnapshots()
  映射为应用层 DTO，转换 codec 名称，补充用户级处理状态
        |
        v
MainWindow 唯一 1 Hz 采样器
  整表替换缓存 + 按计数差计算窗口速率
        |
        +--> 顶部：流数量、正在提交帧的路数、合计预览提交 FPS
        +--> 浮层：单路实际/源分辨率、预览提交 FPS
        +--> 右侧：活动流编码、调度丢帧率、图像处理、视觉分析、不可用项
        +--> 状态栏：活动视频、活动音频与视觉管线上下文摘要
```

所有接口均按值返回。UI 不保存 `IMediaSource*`、`MediaPipeline*`、`AVFormatContext*` 或调度器指针。

## 5. 线程、刷新与生命周期

- `VideoFrameScheduler` 的累计计数和最近尺寸使用原子值；读取不加锁、不等待队列，也不触发 OpenGL 调用。
- `MultiStreamManager` 的流表仍由当前 owner thread 管理；整表快照必须在 Controller/UI 所在线程调用。
- UI 只创建一个 1000 ms 的 `Qt::CoarseTimer`，一次调用获得全部流快照；活动流或视觉管线切换时允许即时拉取一次状态，但不新增定时器。
- 即时拉取距离上一基线不足 500 ms 时只更新静态状态并保留上一速率与计数基线，避免用过短窗口产生尖峰。
- 采样器保存每路上一组累计计数和采样时间。流缺失时整表删除缓存；同一 ID 计数回退时重新建立基线。
- 暂停后累计值不重置，下一有效窗口可得到 `0.0 FPS`；新管线首个窗口显示 `--`。
- `StreamRemoved` 到达时立即清除该 ID 的展示和基线；随后整表采样也会过滤不存在的流。
- `closeEvent()` 和析构阶段先停止指标定时器、清空缓存，再调用 Controller `Shutdown()`。
- 指标刷新只更新顶部、右侧、状态栏和浮层，不每秒重建视频源列表。

## 6. 展示层级

| 区域 | 展示内容 | 不展示内容 |
| --- | --- | --- |
| 顶部摘要 | 当前流数、有效出帧路数、合计预览提交 FPS | 单路编码、丢帧详情 |
| 单路浮层 | 名称、来源/状态徽章、分辨率、预览提交 FPS | 编码、网络丢包、视觉详情 |
| 右侧基本信息 | 活动流编码、调度丢帧率、图像处理和视觉分析状态；网络丢包与推理吞吐明确不可用 | 其他流详情 |
| 状态栏 | 活动视频、活动音频、视觉管线上下文 | 重复 FPS、分辨率和编码 |

小视口继续遵守 Phase 4 的降级顺序：名称优先，技术指标只在宽高足够时显示，不能覆盖底部状态徽章。

## 8. 风险与替代方案

### 8.1 已选方案：累计计数整表拉取

优点是所有权清晰、无逐帧信号、无阻塞锁、流移除时自然整表收敛。代价是 UI 显示最多滞后约 1 秒，符合监控型摘要的刷新需求。

### 8.2 未选：UI 直接读取渲染器

渲染器的 `paintGL()`、纹理上传和窗口重绘计数语义不同，且内部锁覆盖 OpenGL 绘制。直接读取会绕过应用层边界，并可能把采样耦合到渲染锁，因此本阶段不采用。

### 8.3 未选：管线逐帧或周期信号

逐帧信号会扩大事件量；每路周期信号会产生多个定时器和排队生命周期问题。当前 UI 是唯一消费者，单个低频拉取更简单且可控。

### 8.4 语义风险

- `PresentFrame()` 返回 `void`，提交计数只能证明帧已交给预览输出链，不能无阻塞证明 GPU 最终显示。
- 调度丢帧混合同步追帧和预览限帧；本阶段只给出合计并使用准确文案。
- 源编码和源尺寸是初始化快照；动态格式变化需要后续独立的数据源设计。

## 9. 验收

静态验收：

- UI 只调用 Controller 的快照接口。
- 所有指标都来自快照或明确的“不可用”状态，无硬编码运行数值。
- 只有一个 1 Hz 指标定时器，不存在逐帧信号或逐流定时器。
- 移除流和关闭窗口时先清理 UI 指标状态。
- `git diff --check` 无新增格式错误，相关括号和对象名静态一致。

后续运行验收（需用户明确要求后执行）：

- 文件、摄像头和 RTSP 首帧前、播放中、暂停、恢复、停止、移除时的数值变化。
- 1/4/9/16 路下刷新频率、UI 响应和 CPU 占用。
- 断流、重连缺失能力、窗口最小化/恢复、全屏和高 DPI 下的展示。
- 对照日志或外部工具核验编码、尺寸和提交 FPS 口径。
